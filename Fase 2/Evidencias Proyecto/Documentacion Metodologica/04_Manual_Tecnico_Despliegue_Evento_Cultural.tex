\section{Ejecución local}

\subsection{Scraper (Windows)}

\begin{verbatim}
instalar.bat        REM crea venv, instala dependencias y Chromium de Playwright
ejecutar.bat        REM pipeline completo (extraccion + exportacion + sincronizacion opcional)
python -m unittest discover -s tests -v
\end{verbatim}

Las variables de entorno se documentan en \code{.env.example} del proyecto;
incluyen credenciales de Supabase y el endpoint de NVIDIA NIM. \textbf{No}
versionar secretos: el workflow los consume como secretos de GitHub.

\subsection{Frontend}

\begin{verbatim}
npm install
npm start           # ng serve en http://localhost:4200 (o ionic serve en 8100)
ng test             # pruebas (Vitest)
npx ng build --configuration production
\end{verbatim}

En Windows existen además \code{install.bat} y \code{run.bat} para el entorno
local. El frontend se conecta directamente a Supabase mediante
\code{@supabase/supabase-js} con la clave pública anon (gobernado por Row Level Security).
En caso de fallo de red o indisponibilidad remota, la aplicación activa un catálogo
mock en memoria como respaldo de contingencia.

\subsection{Scraper en GitHub Actions (desplegado, en testeo)}

\begin{itemize}
  \item El workflow está desplegado y el equipo se encuentra probando el
        despliegue: correr el pipeline con pruebas y sincronización a
        Supabase, usando secretos de repositorio (nunca credenciales en el
        código).
  \item Evidencia de ejecución: captura \code{Evidencia\_ejecución\_scraper\_en
        \_GitHub\_Actions.PNG} en Evidencias Proyecto.
  \item La periodicidad ya está definida y activa: \code{schedule} con ejecución
        programada diaria a las 23:37 (America/Santiago) desde el 29-09 (el bloque
        \code{schedule} está activo desde el 24-09). Cada ejecución restaura el
        checkpoint previo, verifica secretos, ejecuta la suite de pruebas, extrae
        conservando checkpoints como artefactos (retención 30 días), enriquece los
        pendientes y sincroniza con Supabase. Para dar el despliegue por completado,
        el equipo debe registrar la primera corrida programada completa en verde tras
        la corrección de la prueba dependiente del tiempo (Plan de pruebas, sección 5.1).
\end{itemize}

\subsection{Web en Vercel (plataforma de despliegue)}

\begin{enumerate}
  \item Conectar el repositorio de la aplicación a Vercel.
  \item Configuración de compilación: Vercel detecta Angular o se configura:
        \begin{itemize}
          \item Build Command: \code{npm run build} (o \code{npx ng build --configuration production}).
          \item Output Directory: \code{www} (configurado en \code{angular.json}).
          \item Install Command: \code{npm install}.
        \end{itemize}
  \item Enrutamiento SPA: crear \code{vercel.json} con reescritura hacia \code{/index.html}
        para garantizar que las rutas de Angular (\code{/mapa}, \code{/calendario},
        \code{/auth/callback}, etc.) no retornen 404 en navegación directa.
  \item Variables de entorno: las credenciales públicas de Supabase (\code{supabaseUrl} y
        \code{supabaseAnonKey}) residen en \code{environment.ts} y son seguras para el navegador bajo RLS.
  \item Desplegar y registrar la URL oficial de producción como evidencia del proyecto.
\end{enumerate}

\subsection{De la web a la app: Capacitor (conversión en preparación)}

La aplicación Android es la misma web envuelta con Capacitor; pasos de la
conversión:

\begin{enumerate}
  \item \code{npx cap add android} (si la plataforma no existe) y
        \code{npx cap sync}.
  \item Abrir en Android Studio, compilar el APK/AAB de prueba y registrar la
        evidencia de la compilación.
\end{enumerate}

\section{Solución de problemas comunes}

\begin{itemize}
  \item \textbf{Pipeline detenido a mitad:} los checkpoints en SQLite permiten
        reanudar; volver a ejecutar \code{ejecutar.bat}.
  \item \textbf{Consola del navegador con rechazos de View Transitions:} los
        rechazos benignos ya se suprimen en \code{main.ts}; cualquier otro
        error de consola se trata como falla de la verificación.
  \item \textbf{Puerto 8100 ocupado:} liberar el proceso de \code{ng serve}
        previo.
\end{itemize}
